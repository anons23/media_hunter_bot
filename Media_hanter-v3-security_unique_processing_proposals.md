# Предложения по улучшению уникализации Media Hunter

## Цель

Повысить качество и разнообразие результатов обработки без заметной деградации исходного изображения/звука и без изменения архитектуры Media Hunter.

Текущая оценка качества уникализации: ориентировочно 6.5–7/10.
Ожидаемая оценка после безопасных улучшений: около 8/10.

## Текущий визуальный профиль

```python

def _unique_video_filters() -> str:
    return (
        "scale=iw*0.998:ih*0.998,"
        "scale=iw*1.002004:ih*1.002004,"
        "eq=contrast=1.012:brightness=0.004:saturation=1.015,"
        "unsharp=3:3:0.4:3:3:0.0,"
        "noise=alls=1:allf=t"
    )
```

## Предлагаемое улучшение: контролируемая вариативность

Вместо постоянно одинаковых значений contrast/brightness/saturation можно использовать небольшую случайную вариативность в безопасных пределах:

```python
import random


def _unique_video_filters() -> str:
    """Apply subtle, quality-preserving visual variation."""
    contrast = random.uniform(0.99, 1.02)
    brightness = random.uniform(-0.005, 0.008)
    saturation = random.uniform(0.99, 1.03)

    return (
        "scale=iw*0.998:ih*0.998,"
        "scale=iw*1.002004:ih*1.002004,"
        f"eq=contrast={contrast:.4f}:"
        f"brightness={brightness:.4f}:"
        f"saturation={saturation:.4f},"
        "unsharp=3:3:0.4:3:3:0.0"
    )
```

### Что намеренно НЕ добавлять

- постоянный `noise` в базовый профиль;
- обязательный crop;
- `setpts=0.98*PTS`;
- `atempo=1.02`;
- агрессивные изменения скорости видео или аудио.

Причина: эти изменения могут ухудшать качество, композицию или A/V sync и не дают гарантии какого-либо результата для внешних систем fingerprinting.

## Resize

Сохранять aspect ratio и следить за корректными чётными размерами кадров, необходимыми кодеку.

Не использовать фиксированный crop как обязательный этап обработки.

## Watermark

Watermark должен оставаться отдельным этапом обработки и не смешиваться с логикой визуальной вариативности.

Существующие ограничения watermark и проверки размера необходимо сохранить.

## Проверка результата через ffprobe

После FFmpeg желательно проверять результат до отправки пользователю:

```python
async def _validate_processed_media(path: Path, audio_only: bool) -> None:
    """Validate that FFmpeg produced a usable media file."""
    if not path.exists() or path.stat().st_size <= 0:
        raise RuntimeError("Обработанный файл не создан или пуст.")

    # Далее можно использовать ffprobe для проверки:
    # - наличия нужного stream;
    # - duration > 0;
    # - корректных video dimensions;
    # - отсутствия очевидно повреждённого результата.
```

Проверка должна быть дополнительной защитой и не менять существующую архитектуру обработки.

## Лимиты и безопасность

Не менять следующие ограничения только ради улучшения уникализации:

- `MAX_SOURCE_DOWNLOAD_MB`;
- `MAX_SEND_MB`;
- `SOFT_UNIQUE_LIMIT`;
- `MAX_CONCURRENT`;
- ограничения очереди;
- ограничения watermark;
- существующие SSRF/path/security проверки.

Пользовательский лимит Telegram Bot API в 2 GB не означает, что нужно увеличивать внутренние лимиты Media Hunter.

## Аудио

Не добавлять искусственные `atempo`, highpass/lowpass или другие изменения только ради изменения fingerprint.

Сохранять корректные:

- sample rate;
- bitrate;
- A/V sync;
- отсутствие clipping.

## Логирование

Если параметры вариативной обработки логируются, записывать только безопасные технические параметры. Не логировать cookies, токены, приватные URL с чувствительными параметрами или содержимое пользовательских файлов.

## Тесты

Добавить/обновить тесты для:

1. корректности строки FFmpeg-фильтров;
2. допустимых диапазонов random-параметров;
3. отсутствия постоянного `noise` в базовом профиле;
4. проверки обработанного файла;
5. обработки повреждённого/пустого результата;
6. сохранения существующих лимитов и security-проверок.

## Важное ограничение

Эти изменения являются улучшением качества и разнообразия обработки. Они не являются гарантированным способом обхода систем fingerprinting, Content ID или иных платформенных механизмов обнаружения совпадений.

## Рекомендуемый порядок реализации

1. Прочитать актуальные `processor.py`, `config.py`, `handlers.py` и `tests/test_security.py`.
2. Не переписывать архитектуру.
3. Не менять лимиты.
4. Добавить контролируемую вариативность визуальных параметров.
5. Сохранить watermark отдельным этапом.
6. Добавить/усилить post-processing validation через `ffprobe`.
7. Не добавлять `atempo`, `setpts`, обязательный crop или постоянный noise.
8. Запустить все тесты и CI.
9. После изменений провести повторный аудит ветки.
